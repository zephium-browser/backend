# Cloud policy and credits

`config/cloud.json` is the owner-controlled default policy. It starts with `enabled: false`, no enabled models, and zero allowances until the owner chooses products and rates. Provider API keys belong in environment secrets. The repository fixtures are test data, not production prices or provider approvals. Local tests use injected providers and need no live credentials.

## Review and activation

The owner reviews each proposed change, increments the positive `revision`, and validates the candidate environment, drains old services, and explicitly runs `cloud:register` with the migrator role before starting the candidate API/worker. Startup only verifies the active revision and digest; it cannot activate a policy. A revision cannot be reused with different content; the active database revision only moves forward. Keep the prior policy records for existing grants, orders, and requests. Enabling a model requires a reviewed, nonzero price table and a `pricingSource`, plus request, context, output, search, concurrency, and provider rate limits. Verify current provider pricing and response formats before activating a model. A configured key alone does not make a model available.

Plan IDs, the free-plan identity, and each subscription product’s plan/cadence mapping remain stable across revisions. Retire a subscription offer with `checkoutEnabled: false`; existing subscribers retain its entitlement mapping, while new checkout no longer offers it. A new price/product can replace that offer under the same plan. Policy registration rejects removing or remapping existing products or plan IDs.

Policy plans define integer allowance units, a cycle, concurrency, requests per minute, and an optional daily cap. The hosted default is a one-time free signup allowance (`cycle.kind: "once"`) without expiry and a monthly paid cycle. Set welcomeUnits to zero for once-only free plans: this replaces, rather than supplements, the former welcome grant. Legacy recurring and welcome policies remain supported for self-hosters. No automatic overage charge or balance refill follows a request that exceeds available grants.

One display credit is **10,000 integer accounting units** (`credit_units:"10000"`). For USD-denominated Zephium usage credit, **100 credits = USD1 face value**, so USD1 is 1,000,000 units. `unit_scale:1000000` remains a compatibility field, not the display-credit divisor. Rates are policy values for input, cached input, cache writes, output, and native search calls; charging uses integer arithmetic. Credit grants record their original amount and end date. Editing policy does not resize or shorten an existing grant. A purchase uses the product rule from its original policy revision and order time. Each admitted request stores its own price snapshot, so a later rate edit does not reprice it.

Eligible grants are spent by expiry order. A request reserves a conservative admission budget before provider dispatch, then settles against reported actual usage and releases unused hold. When usage cannot be confirmed, the hold remains through a short recovery window and is then refunded; Zephium absorbs the provider cost. There is no automatic generation replay. Clients may send an `Idempotency-Key` to guard a retry; a repeated key cannot charge or dispatch twice. Account deletion and refunded top-ups can block further spending pending review.

## Provider boundaries

Native OpenAI, Anthropic, and Jev (TypeSafe) adapters are the first activation candidates. Google, OpenRouter, and DeepSeek adapters are present with request and response limits, but need individual live checks and reviewed prices. Google hosted search is unsupported until there is a bounded cost and usage contract. Search is only a supported provider-native tool; there is no standalone search vendor or separate search billing path.

OpenAI native web-search items are charged per completed `search`, `open_page` or `find_in_page` action at the configured search-call rate. The provider guide documents the search-call fee but not a separate page-open/find fee, so each action is billed conservatively as a search call rather than refunded. Any other or incomplete action keeps the response as unknown usage.

Admission uses local, conservative estimates of the full native JSON request, including history and tool schemas; text-only requests make no upstream token-count round trip. Text multipliers and framing margins are admission assumptions, not provider guarantees. Embedded PNG/JPEG inputs keep the full-context provider-cost reservation. For OpenAI, Anthropic and Google, a native image token count refines only the customer hold, with a five-second deadline and a 64 KiB response limit. It includes history and tool definitions; output-schema configuration omitted by counters is covered separately, and the existing framing margin is retained. Counting failures stop generation without charging; there is no optimistic fallback. Other providers retain their full-context image hold. Remote media URLs and unsupported media are rejected rather than fetched. Native search reserves additional input and bounded tool-call fees. Settlement uses actual reported usage, never an estimate of missing usage. An overrun above a hold is absorbed and reported as an aggregate operational event, not charged beyond the approved reservation. Search, cache, and reasoning categories must be complete enough to determine the charge; ambiguous usage follows the hold-and-refund path.

The gateway does not store prompts, outputs, browsing history, screenshots, or tool payloads. It stores policy revisions, grant and request state, usage counts, model/provider identifiers, and bounded operational information needed for billing and recovery. Live provider routing and production prices remain unverified until each configured integration is exercised with its own credentials.

## Desktop policy additions

Models include one-line `description`, `tier` (`fast`, `balanced`, `frontier`), `maxDurationMs`, and `idleTimeoutMs`. The API returns globally enabled/configured models, including paid models with `available:false` for a free account; disabled placeholders are absent. `defaults` maps each plan to explicit lead/page/light/decision/transcribe model IDs. The validator rejects a default that the plan cannot use or whose role is unsupported. Keep at least one evaluated fast default search-capable when activating hosted Work; Google hosted native search remains disabled.

The default free allowance is once-only with no expiry and no additional welcome bonus. Pro renews once per calendar month even when billed annually. Initial concurrency ceilings are eight free and twelve Pro, alongside the shared global/provider limits. No production allowance or price is implied by these defaults. Top-up products should use a 365-day expiry at launch. Grants are always consumed in earliest-expiry order, including when a purchased grant is nearer expiry than the plan allowance.

Default generation caps are 90 seconds without upstream bytes and ten minutes overall. Jev remains capped at fourteen seconds. Timers use provider bytes, not downstream keepalives; worker leases cover the same overall cap. Provider bytes are forwarded at complete SSE event boundaries with bounded buffering. A final Zephium SSE comment reports settled/pending accounting or an interruption error; final `charged` is included only for settled accounting. Broken connections or process loss can prevent trailer delivery. The receipt endpoint is the fallback, and generation is never automatically replayed.

Welcome and current free-period eligibility survive account deletion as keyed email digests, timestamps, and canonical alias links. They contain no address or browsing content but are pseudonymous abuse-prevention records, not anonymous data. This stops deletion, re-signup, and email changes from resetting grants. Keep `ELIGIBILITY_SECRET` stable and backed up independently of rotating abuse/session secrets; changing it without a migration resets that protection. Existing grant amounts and request prices remain frozen. The usage API exposes welcome credit separately as `bonus_remaining` and `bonus_expires_at`.

`selfHostedPlan` is null on Zephium-hosted deployments. A self-hosted instance can select its own plan without Polar using `DEPLOYMENT_MODE=self_hosted`, `BILLING_ENABLED=false`, and `config/self-host.json`. Operator-defined quotas and keys are independent of Zephium Cloud balances. A hosted API/worker refuses a policy selecting a self-hosted plan.

## Deployment spend and uncertain usage

`limits.budgets` is independent of customer credits. All amounts are integer USD micro-dollars (1 USD = 1,000,000); models require reviewed positive `costRates` in the same per-million-token/per-call shape as customer rates. `scope` is stable across policy revisions, so changing the policy cannot erase spend. Total and UTC reservation-day buckets count active reservations, settled provider costs, and unreconciled exposure. These content-free records survive account deletion. Refunds to customer credits do not refund unknown provider exposure. Provider tariffs must conservatively cover context pricing tiers; upstream overrun/price changes can still exceed an estimate, so use independent provider hard limits as another control.

Staging is limited to $50 total and $10 per UTC reservation day. Its free subsidy sub-budget is $5/day to exercise that cutoff separately; these are test settings, not approved production prices. The production template has daily/free caps zero and cloud disabled. A total cap has no automatic reset; increase it only through a reviewed revision. A daily cap resets at UTC midnight. Worker alerts at 80% of any configured cap without customer attribution.

When the free subsidy reservation cannot fit, only purchased grants are eligible for a free account. Top-ups do not change model access. Pro usage bypasses the free subsidy cap, but still obeys the deployment safety ceiling and its own allowance/daily limits. Grants within the eligible funding sources remain ordered by expiry. Receipts/history expose funding_source; usage exposes free_usage_paused and purchased_usage_available. A false paused flag does not promise that every request's reservation fits the remaining pool.

`unconfirmedRequestsPerUserDay` defaults to three. Repeated unknown/refunded requests stop new admissions with retryable usage_confirmation_limited. A customer who disconnects (Stop) after dispatch is not an unknown request: the server aborts the provider call and settles with `error_class: client_disconnected`, charging provider-reported partial counts where streamed (Anthropic input, Google usage metadata) and otherwise the admission input estimate plus delivered output at three UTF-8 bytes per token, capped at the hold. Provider-cost exposure for such estimates keeps a 2x output margin for unstreamed reasoning, also capped at the hold. Customer daily limits retain the original reservation for unknown refunded calls. Concurrent requests already admitted may finish; the independent deployment cost budget is the backstop. `maxFreeConcurrent` reserves global stream capacity for paid traffic (24 free slots out of 32 overall in hosted templates); it is not a provider availability guarantee.

## Transcription

Only exclusive OpenAI transcribe rows use the multipart route. Models specify native context/output ceilings because this API has no output-token limit parameter. `audioInput` is the per-million audio-token rate; `audioMinute` is an explicit successful missing-usage duration tariff. A duration tariff never becomes invented token usage. Missing token usage preserves the full provider-cost exposure even after customer duration settlement. Malformed usage stays pending and failed/aborted transcription never creates a duration charge. Keep native limits/rates reviewed when replacing a model.

`config/staging.json` contains Luna lead/page/light, mini-transcribe for Free/Pro/Max, and full transcribe for Pro/Max unlock testing. Staging allowance fixtures are Free250 credits once, Pro2,000/month and Max10,000/month; they are provisional and do not resize existing grants. Staging credit tariffs are test values; Luna uses the conservative standard long-context ceiling. Polar product mappings remain empty until configured. Provider-native Anthropic beta headers remain disallowed. Jev is unused and disabled for this release.

## Credit denomination and migration

Customer `rates` are retail tariffs and must include the intended margin; `costRates` remain independent provider-cost estimates used for deployment safeguards. Changing the presentation scale does not change either tariff or round charges to whole credits/cents. For example, 6 accounting units remain exactly 0.0006 credits. Polar product prices use currency minor units, not `credit_units`.

USD top-ups must match the configured fixed listed USD price: USD1 buys 1,000,000 units / 100 credits; USD5 buys 5,000,000 units / 500 credits. Taxes added at checkout and processor fees are not credit multipliers. Offers and fresh checkout preflight reject mismatched units/currency with `product_configuration_invalid`; keep provider product prices and the reviewed policy coordinated. Legacy undeclared-currency/self-hosted policies retain their existing arbitrary-unit behavior until explicitly migrated.

Activating `creditCurrency:"USD"` is a financial migration, not a display toggle. Drain API/worker activity, settle/reconcile legacy purchases, wait for old checkout safety windows, and review any remaining purchased balances before explicit policy registration. Registration rejects outstanding balances, unresolved checkout windows and relevant pending reconciliation. It shares an advisory transaction fence with top-up settlement without giving runtime roles write access to policy tables. A late unlabelled historical top-up cannot silently mint newly denominated USD credits: it stays ungranted for operator review (`purchase_policy_unavailable`). Refund tombstones and original grant/request snapshots remain authoritative.

The October20 denomination decision is approved; allowance sizes and retail margin still need final product approval. A prepared policy revision or repository fixture is not evidence of live activation. Before switching staging, inspect its active revision and reconcile all old test purchases; do not edit old grants or reuse a policy revision to make the migration pass.

Rates may include `longContext: { inputTokensAbove, rates }`. The threshold is exclusive and counts all provider-reported input categories, including cache reads and writes, but not output/reasoning. Above the threshold the long-context rates apply to the entire request. Admission selects a tier using its conservative input bound; settlement independently selects using actual usage from the immutable request tariff snapshot. Historic flat snapshots remain valid. Long-context rates cannot be below base rates. Audio rows do not use this feature. The catalog exposes the optional `price.long_context` counterpart. OpenAI 12-hour cache writes (request-level and explicit breakpoints) are rejected until separately supported; default 30-minute writes use the historical short-cache-write accounting category.

If otherwise sufficient credit is temporarily held by concurrent requests, admission returns `429 credit_reservation_pending` with `Retry-After` (1–60 seconds), instead of `402 insufficient_credits`. This is a suggested recheck interval, not a promise that the in-flight call will have finished. A genuine shortage remains 402. Native search continues to reserve one full context per permitted call for both customer and provider exposure. Provider budgets, quota buckets, daily caps, unknown-usage recovery, and actual-usage settlement are unchanged.

Native image-count contracts: [OpenAI](https://developers.openai.com/api/docs/guides/token-counting), [Anthropic](https://platform.claude.com/docs/en/build-with-claude/token-counting), [Google](https://ai.google.dev/api/tokens). Token counts do not determine the final bill; reported generation usage does.
